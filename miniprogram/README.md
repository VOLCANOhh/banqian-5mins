# 班前五分钟 · 小程序（工人端 + 管理端一体）

原生微信小程序，无框架无构建。打开方式：微信开发者工具 → 导入本目录。
**一个程序两端，码 > 身份**：扫门口码进工人学习流（普通页，无 tabBar），扫管理员码进管理端三界面（底部 tabBar）；不扫码直接打开时按 `/api/me` 的 openid 角色分流（路由详情见 PROTOCOL §10 末）。

**前后端协议与交接文档 → [PROTOCOL.md](PROTOCOL.md)** —— 后端/联调前必读。

## 跑起来

1. `project.config.json` 里 `appid` 已填正式 AppID
2. 开发者工具 → 详情 → 本地设置 → 勾"不校验合法域名"（联调期）
3. `config.js` 里 `USE_MOCK: true` 时全部走假数据，后端好了改 `false` 并填 `API_BASE`
4. 演示管理端：`config.js` 里 `MOCK_ROLE` 改 `'admin'` 再编译（工人端改回 `'worker'`）

## 架构一句话

**前端是渲染器+执行器，后端是导演。** 后端下发剧本 `steps[]`（say/ask/show/action），
说什么、何时问、答完是否强调全在 JSON 里；前端只做字幕、大圆钮、录音上传。

## 工人端流程（全程一屏，无跳转无表单）

打开 → 品牌启动页 → me（角色分流）→ getSession（下发剧本）→ 逐 say 步字幕滚（三级灰度+顶部进度条）
→ ask 步自动读题 → 自动开录（声波面板+秒表）→ /api/answer → 反馈弹卡（✓绿/⚠橙+振动）
→ next_steps 插回队列（**追问式考官**：答对→情景变式追问、模糊→钻一层、答错→强调重问）
→ 剧本走完 → finish（**随送行为埋点**：暂停/重听/答题用时，进学习档案）→ result 页（得分+「今日已完成」印章+复训日历卡）

- 标题/正文/题目/你的回答，全在同一条歌词流里滚
- say 步期间右上角红点 = 指令监听中（录音→/api/command→动作 JSON）
- 语音 Key 只在后端，前端只传音频文件

## 管理端三界面（pages/admin/，底部 tabBar）

| 界面 | 说明 |
|------|------|
| 推送 | 主界面 = **推送记录**（每次推送的人员/日期/内容，圆角卡片按日期分组，顶部检索，点卡片看规范明细）；「＋添加今日推送」→ ①先选人（全部/分组/个人）→ ②今日干什么活：**管理员自己说/填**（「按住说话」语音输入；边输边联想历史推送 + 近两天推送一键沿用，规范跟着走）→ ③备注 → 推送（推送时系统按工序自动匹配规范，管理员不选条文，可先点"看看会匹配到哪些规范"预览） |

管理端底部 tabBar 第四栏是**设置**（版本号/运行环境/数据模式/客服/隐私声明），工人端无 tabBar 不可见。
| 学习情况 | 顶部姓名检索栏；今天（未学橙区置顶+一键提醒、已学绿区）/往期（日期可检索，近14天列表→当天明细）；点工人卡片进详情 |
| 工人 | 分组管理（添加分组、组内添加工人）；医院式规范表单：分区/即时校验/手机号 3-4-4 分段/列表脱敏/隐私声明 |

**工人详情页**（workerDetail）：A 档案状态卡（今日得分/未学）→ B 薄弱点TOP3（掌握度条+「为他推送巩固内容」）→ C 累计/连续/平均 → D 复训计划（记忆保持率，算法估算）→ D+ 行为诊断（暂停/重听行为分析）→ E 近期记录时间线（展开错题：他的回答 vs 正确答案）。

管理端入口对工人不可见；真正的保密在服务端——admin 接口按 openid 鉴权，工人调用一律 403。
