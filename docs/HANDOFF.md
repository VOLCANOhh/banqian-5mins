> 读者：全体接手者——做特征函数的（袁博伦）、做 RAG 与资料库的（同学）、做编排器的（马知远）、以及任何新接手的 AI 会话。
> 本文件是唯一事实来源。代码与协议细节以 `miniprogram/PROTOCOL.md` 为准；本文件负责讲清**是什么、有什么、谁做什么、接口在哪**。

## 1. 项目详解

### 1.1 一句话

「班前五分钟」——面向建筑工人的**个性化安全微培训智能体**：把每天政策强制但流于形式的"班前晨会 5 分钟"，变成按人定制的语音微培训。山东大学首届「海之子」杯智能体创新大赛参赛作品（选题：工友与员工·技能提升）。

### 1.2 行业背景（数据来源均可引）

- 全国农民工 30,115 万人，其中建筑业约 4,156 万（13.8%）；四年减少 25.2%（2021→2025）
- 平均年龄 43.3 岁，50 岁以上占 32.0%；月收入增速 2.4%，近十年最低
- 46 岁以上占比 57%、青年年流失率超 12%、仅 6% 接受过智能设备操作培训、72% 依赖师徒制（南京市政协个案，口径不同仅用于说明趋势）
- 来源：国家统计局《2025 年农民工监测调查报告》（2026-04-30）

### 1.3 政策背景（天然的落地通道）

- 住建部/人社部《建筑工人实名制管理办法（试行）》：先培训后进场；1 年以上无数据更新须重新培训
- 山东省住建厅《班前"晨会"活动指南（试行）》（2023-05）：**每班作业前晨会不少于 5 分钟，签字归档并纳入日常监督检查**；江苏、广东有同类强制规定——多省文件均强调"切忌形式主义"，侧面印证执行现状
- 国务院《关于深入实施"人工智能+"行动的意见》（2025-08）：AI 垂直落地
- **关键洞察：强制 5 分钟不是障碍，是免费入口**——流程已存在，我们只把"念本子"换成"个性化"

### 1.4 痛点咬合逻辑

| # | 痛点 | 证据 | 推导 |
|---|------|------|------|
| 1 | 培训效果会"过期"，行业按一次性事件处理 | 记忆衰减研究共识 | 一次性学习保持率快速下降，分散复习可延缓 |
| 2 | 制度按年、衰减按周 | 法定年训 vs 保持周期 | 空白期即事故高发期；**不替代法定培训，填补空白** |
| 3 | 班前会形式主义 | 政策文件自证 | 内容与当日工序无关、不考虑个人薄弱点 |
| 4 | 人群老龄化与技能断层 | 南京个案数据 | 交互只能是"听与答" |
| 5 | 事故高度集中 | 高坠 59.07%、物体打击 12.05%（建办质〔2021〕17号） | 少数高频险种的精准培训边际价值极高 |

### 1.5 核心闭环

```
管理员说"今天干什么活" → 系统生成"今天学什么" → 工人"听+答+随时问" → 数据回流 → 下次更准 + 管理员看得见
        六角色：工序解析 → 规范检索 → 学情诊断 → 内容生成 → 考评 → 复训调度（另设：答疑、质检）
```

### 1.6 差异化与边界

- **优化"培训时机"而非"培训内容"**：内容再好也会衰减，频率与时机才是杠杆；以对照实验（复训组 vs 单次组，30/60/90 天保持率）标定复训参数——实验本身即核心交付物
- 零硬件、扫码即用、依托现有实名制与班前会流程；弱网优先（内容预生成+本地缓存）
- 数据伦理（申报书承诺，产品上已体现）：学习档案仅用于个人技能成长，不作绩效考核或处罚依据
- 技术保守决策即得分证据：成熟大模型 API、不训练自有模型、不引入重型向量库、前端无构建

### 1.7 两层关系（产品龙骨）

| | 管理员（班组长） | 工人 |
|---|---|---|
| 角色 | 触发者 + 监督者 | 零操作消费者 + 数据共建者 |
| 只做 | ①今天干什么活 ②谁是我的人（录档案发码） | 扫码、听、说、不懂就问 |
| 不做 | 不选条文、不生产内容、不判断谁该学什么 | 不选内容、不操作界面、不需识字 |
| 得到 | 数字化台账（班前会"签字归档"的合规承接） | 针对性 5 分钟（含他上次答错的点） |

**电源开关在管理员手里**：他不推工序，工人端就是空壳；管理端是另一半发动机。

### 1.8 架构哲学（三条铁律）

1. **确定性层 × 模糊性层**：函数做确定性的事（调度/统计/匹配/降级），AI 做模糊性的事（理解语言、生成内容、消化新文档）。不拿规则引擎冒充 AI，也不拿 LLM 干算术。
2. **内容现做**：系统不存预制培训内容；规范库是原料、学习档案是证据，剧本由编排器预生成，管理员预览确认后发出——同时满足弱网优先。
3. **trace 可审计 + 降级不断链**：每份剧本附六角色证据链；LLM 挂 → 最近一次成功剧本 → 预生成池；判分挂 → unknown 待人工复核。

## 2. 服务器工作机制通俗详解

### 2.1 四个角色，一顿火锅

把服务器想象成火锅店后厨：

| 角色 | 比喻 | 本质 | 在咱项目里 |
|------|------|------|-----------|
| **编排器** | **店长**：不炒菜，拿流程单指挥谁先谁后、出岔子怎么办 | 纯函数（流程控制代码） | `server/index.js` 长成的 orchestrator |
| **agent 组**（六角色+答疑+质检） | **六个工位**：切配/炒料/摆盘，各有专职 | 角色定义+输入+输出 schema 的任务单元 | 工序解析/规范检索/学情诊断/内容生成/考评/复训调度 |
| **RAG** | **采购员+库房**：厨子不凭空做菜，先按单取料、料摆案板再下锅 | 检索（找资料）+ 增强（把资料塞进模型输入） | 规范检索=取料；内容生成看着规范原文写剧本=下锅 |
| **特征函数** | **老师傅的分析手册**（不是库管员！） | 见 §2.2——这是本项目核心创新 | 规范分析/工序分析/学情分析/判分/追问/指令 |

### 2.2 特征函数的正确定位（已修正，旧版"打标签"理解作废）

**它不生产标签，它规定"怎么分析"。**

| | 传统固定程序 | 我们的特征函数路线 |
|---|---|---|
| 判断方式 | 量化：一切写成公式，程序算分 | **非量化：AI 智能分析** |
| AI 的角色 | 没有，或只是工具人 | **分析的执行者**——读得懂语义、处理得了库里没见过的场景 |
| 人的角色 | 写公式 | **写"如何分析"**：分析哪些维度、各因素权重是什么、结果往哪个方向导 |
| 遇到新东西 | 公式覆盖不了就死 | AI 按既有分析方法照样能分析 |

一句话：**我们不写"判断的公式"，我们写"分析的方法"。** 特征函数 = 给 AI 的分析方法规定义：`{ 分析对象类型, 维度清单, 各维度权重与规则（定性为主、数值为辅）, 结果导向声明, 输出 schema, few-shot 示例 }`。AI 的智能负责"分析得动"，特征函数负责"分析得对"。

大纲里"本地添加库后，LLM 将学习开发者设置的特征函数建立新的特征函数"= **分析范式的迁移生长**：新文档进来，AI 参照已有函数的分析方式为它草拟新特征函数，**人工确认后入库**（马知远终审——方法论是裁判规则，必须有人的确认环）。

特征函数是模糊性层所有分析共享的方法论资产：

```
            特征函数库（开发者设计的方法论）
            ├─ 规范分析函数：这条规范多重要、何时该讲、对哪些人
            ├─ 工序分析函数：今天这活儿的风险结构是什么
            ├─ 学情分析函数：这个工人今天最该被提醒什么
            ├─ 判分函数：怎么判、partial 边界、导向=鼓励优先
            ├─ 追问函数：何时追问、问什么、何时终止
            └─ 答疑函数：只按当日 RAG 命中集回答、超纲转人工（§4 铁律）
                        │
   RAG 检索 ──┬── 剧本生成 ──┬── 考评判分 ──┬── 追问/答疑 ──┬── 推荐分析
        （全部按特征函数规定的框架执行，而不是各写各的 prompt）
```

### 2.3 这家店的一天（服务器完整时序）

```
早上 06:30 【管理员推送】AI 推荐卡（确定性层）→ 预览确认 → 确认推送今日工序「三层外墙脚手架搭设」
推送同时 【剧本生成管线】（编排器主导，推送即生成）
  → 特征函数（工序分析）出工序特征（工种=架子工，风险=高坠/物体打击）
  → RAG 按特征命中 JGJ80 第4.2.1条、第5.1.3条（原文+文号）＝【当日命中集】
  → 学情诊断翻档案：王建国连墙件 09-28 答错过
  → 内容生成看着命中集+错题写出今日剧本（文案+考题）
  → 质检员自检：引用的每条规范都在命中集里吗？有编造吗？不过→重生成/降级
  → 剧本+trace+【命中集】随任务存档（generated_at=推送时刻）

早上 07:00 【工人学习】扫码即播；听不懂随时打断 → §4 答疑通道
答题时   【考评工位，实时】ASR → LLM 语义判分 → verdict + 追问策略
学完     【归档+排期】成绩+行为埋点进档案 → SM-2（纯函数）算复训日 → 飞轮闭环
```

### 2.4 每个板块的输入和输出

| 板块 | 输入 | 输出 | 函数还是模型 |
|------|------|------|-------------|
| 特征函数 | 分析对象（规范/工序/档案/答题）+ 方法论定义 | 带理由的分析结论（按输出 schema） | **LLM + 方法论** |
| RAG 检索 | 工序特征 JSON | 命中规范条目（原文+文号+匹配分） | **函数**（特征打分；几十条不上向量库） |
| ① 工序解析 | task_text | 结构化工序特征 | 特征函数 |
| ② 规范检索 | 工序特征 | 当日命中集 | =RAG |
| ③ 学情诊断 | 工序 + 该工人档案/错题 | 薄弱点清单+证据 | 函数统计打底 + 特征函数组织结论 |
| ④ 内容生成 | ①②③的产物 | 剧本 steps（文案+考题） | **LLM**（核心生成） |
| 质检 | 剧本 + 命中集 | 过/不过 + 理由 | LLM 自评（防幻觉闸门） |
| ⑤ 考评 | ASR 后的答题文本 | verdict + 追问 next_steps | **LLM**（语义判分） |
| 答疑 | 工人问题 + **当日命中集** + 当前步 | 回答 say 步（+可选改写） | **LLM**（锚定命中集，铁律 §4） |
| ⑥ 复训调度 | 掌握度 + 距上次天数 | 下次复训日期 + retention | **纯函数**（SM-2） |
| 指令意图 | 8s 语音分片/插件文本 | 动作 JSON / none | ASR + 小模型分类 |

### 2.5 三个易混点（钉死）

1. **特征函数 ≠ RAG**：特征函数定义"怎么分析"；RAG 是"按分析结果找料+看着料做菜"。
2. **编排器 ≠ agent**：编排器是流程代码（函数），agent 是工位。六角色是架构叙事不是调用次数——⑥是纯函数，质检是自评，实际模型调用可控在 4-6 次/日级批量。
3. **RAG ≠ 向量库**：规范库几十条，特征打分就够。卖点是**特征结构化**，对上申报书"不引入重型向量库"。

## 3. 编排器：五条管线（流程的完整确立）

编排器只管四件事：**顺序、传递、兜底、留痕**。它自己一个模型都不调。

### 管线 A：入库（开发者库/本地库，异步，人工确认环）

```
新规范文件
→ ①匹配既有特征函数？ ├─ 有 → 用它分析
                     └─ 无 → LLM 参照已有函数草拟新函数 → 人确认（马知远）
→ ②按特征函数分析 → 特征 JSON + 原文出处
→ ③人确认（规范准确性终审）
→ ④入 KB 库，可被检索
降级：LLM 失败 → 进待审队列，绝不阻塞
```

### 管线 B：剧本预生成（每日批量 + 推送时触发）

```
今日任务（task_text × kb_ids × target）
→ ①工序分析 → 工序特征
→ ②RAG 检索 → 【当日命中集】
→ ③学情诊断（目标对象档案）→ 薄弱点清单
→ ④内容生成 → 剧本 steps
→ ⑤质检员自检（引用全在命中集？有编造？）→ 不过 → 重生成 1 次 → 降级
→ 存预生成缓存（draft：steps + trace + 命中集）
```

### 管线 C：工人学习（实时）

```
C1 打开 /api/session/today
  → 查预生成缓存 ├─ 有 → 直接返回（快、弱网可）
                └─ 无 → 现场跑管线 B 简化版 → 生成即缓存

C2 答题 /api/answer（每题一次）
  → ①语义判分（判分特征函数：verdict 定义、partial 边界、鼓励优先）
  → ②追问决策（correct→变式 -var / partial→钻一层 / wrong→换讲法 -re）
  → ③写答题记录
  降级：LLM 挂 → unknown、不追问、主流程继续、记待人工复核
  铁律：追问深度 ≤2 层，-var/-re 步答完即止

C3 打断提问 /api/ask → 见 §4

C4 结束 /api/session/finish
  → 算分（函数）→ 掌握度更新（规则）→ SM-2 排期 → 埋点入库 → trace 组装
```

### 管线 D：管理端分析

```
D1 AI 推荐 /api/ai/recommend：确定性扫描出候选 → LLM 按推荐分析函数组织理由；规则引擎兜底
D2 看板/详情/往期：纯函数统计，永远不经 LLM——快、稳、可复现
```

### 管线 E：语音指令（实时，高频）

```
分片 → ASR（方言模型，worker.dialect 映射 appkey）→ 意图分类（置信度阈值）
  ├─ 阈值以下 → none（工地说笑绝不误判）
  └─ 以上 → 动作 JSON（pause/resume/set_font/set_volume/repeat/ask/next/none）
已知风险：TTS 回声录回 → 抗回声 or PTT 兜底（PROTOCOL §5）
```

### 编排器代码结构（建议）

```
orchestrator/
├─ pipelines/   五条管线（A 入库 / B 预生成 / C 学习 / D 分析 / E 指令）
├─ roles/       六角色 + 答疑 + 质检员（统一模式：输入校验 → 执行 → 输出 schema 校验 → trace 追加）
├─ features/    特征函数库（袁博伦）
├─ rag/         检索打分（同学）
├─ llm/         三通道客户端（智谱→阿里→火山，统一接口+自动降级）
├─ store/       数据层（内存桩 → JSON 文件 → SQLite）
└─ trace.js     证据链组装
```

**双保险约束 AI**：特征函数管"分析方向对"（方法论），输出 schema 校验管"输出形状对"（工程）——两层都写死在 roles 里。

## 4. 阅读机制：语音助手式（含答疑锚定铁律）

> 协议已实现：PROTOCOL §11 打断提问通道（`/api/ask` + `replay_current`/`drop_rest` + 前端 spliceAsk/tapAsk）。本节确立**后端知识来源**的铁律。

### 4.1 工人端交互时序

```
朗读中（phase=read，任意 say 步）：
  工人点「没听懂 ?」悬浮钮，或直接说"不懂/什么意思/为啥"（command ask 动作）
  → 暂停 TTS/指令监听/滚动 → 录问题 ≤30s → 文字入字幕流"你的问题：…"
  → POST /api/ask {session_id, step_id, question}（stageText="老师傅在想…"）
  → 响应 {steps[], replay_current, drop_rest}
  → spliceAsk 拼接：queue = q[0..i) + steps + (replay_current ? [被打断的步] : []) + (drop_rest ? [] : q[i+1..])
  → 继续执行
```

### 4.2 答疑锚定铁律（本项目的防幻觉闸门）

```
推送时：工序 → 特征函数 → RAG 命中集 {kb01, kb02, …} → 剧本生成 → draft
                                    │
                                    └── 命中集随 session 存留 ──────┐
白天朗读中：工人问"连墙件是啥意思？"                                │
  → /api/ask → 答疑角色：只在【当日命中集】里找答案 ◄─────────────┘
     ├─ 有 → 大白话回答（引用条款，一两句能听懂）
     └─ 没有 → "这个得问你们安全员，我记下来了"（超纲转人工 + 记待审 → 反哺本地库）
```

**为什么是这个铁律（三层防线）：**
1. 不能只凭剧本文字答——剧本是生成物，信息有损（压缩过的口语版）
2. 不能脱离当日 RAG 结果答——脱离命中集就是自由发挥，安全场景不允许
3. 命中集之外的 → 转人工——这不是无能，是**边界诚实**（申报书"数据伦理/不虚构"同源的工程表达），还顺手收集了本地库的新素材

### 4.3 问答环节（模型全权）

`/api/answer` 契约字段不变（verdict + next_steps），但**问不问、问哪道、怎么评、答完是否强调，全部由后端模型按追问函数决定**。前端只 splice。追问类型表见 PROTOCOL §4。

## 5. 系统架构全景
