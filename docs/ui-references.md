# UI 对标调研：成熟小程序都怎么做

> 用途：「班前五分钟」UI 成熟化改造的对标依据。全组（含另一个对话）共用。
> 来源：工信部《移动互联网应用(APP)适老化通用设计规范》(2021)、微信小程序设计指南 / WeUI 官方规范、各产品公开设计模式整理。
> （注：本机外网受限，本文按权威规范与主流产品既有设计模式整理，规范条款均为公开发布内容。）

## 0. 硬性规范打底（这些是"及格线"，不是风格）

**工信部适老化通用设计规范（适老版强制要点）**
- 字号：适老版默认明显大于标准版，且必须提供再调大的入口
- 对比度：正文文本与背景 ≥ 4.5:1；大字号（≥18pt）≥ 3:1
- 点击区：可操作元素 ≥ 48×48 dp（我们的工人端主按钮 240rpx 圆钮已远超，保持）
- 操作反馈：任何操作必须有即时反馈——文字、声音或振动至少其一
- 禁止项：无广告、无诱导按钮、无自动弹窗、无超过安全阈值的闪烁
- 表单：数字输入自动弹数字键盘；避免图形验证码

**微信小程序设计指南 / 关怀模式**
- 跟随系统字号：微信「关怀模式」开启后，小程序应整体跟随放大（我们的产品本身就是大字版，要保证 xxl 档不炸版）
- 控件语义化：按钮有明确文字或无障碍标签（评审里可能有懂无障碍的老师，这是隐藏加分项）
- WeUI 视觉语言：主按钮实心圆角、次按钮描边；列表 1px 分隔线；半屏弹窗从底部圆角弹出、主操作在最下；Toast = 图标+短文案；空态 = 插画+一句说明+一个主按钮

## 1. 六类前辈，各抄一招

### A. 适老化大字产品 → 工人端的"信任感"
**代表**：支付宝长辈模式、银行 App 大字版（工行/招行）、微信关怀模式、国家医保服务平台

| 他们怎么做 | 我们抄什么 |
|---|---|
| 首页只有 3~4 个大宫格，一屏一件事 | 工人端保持"零菜单"，但每一步都要"一屏一个意思" |
| 主按钮永远屏幕底部最大 | 已有（大圆钮），保持并加按压反馈 |
| 操作完成有大字确认页（"转账成功"特大号） | **答题对错、学习完成必须有"确认页"级反馈**——对/错弹卡 + 完成页大字 |
| 高对比、无装饰、无插画堆砌 | 工人端删掉一切非信息元素；颜色只服务状态（蓝=进行、绿=完成、橙=注意） |
| 振动+声音双反馈 | 答题判完加 `wx.vibrateShort`，接 TTS 后加提示音 |

### B. 音频字幕跟随 → 我们的歌词流
**代表**：喜马拉雅听书、微信读书听书、得到、网易云歌词

| 他们怎么做 | 我们抄什么 |
|---|---|
| 当前行居中，上下行按距离分 3 级灰度 | 现在只有 2 级（当前/其他），**加中间过渡级**：相邻行浅灰可读，远处更淡 |
| 顶部有进度条 + 已播/总时长 | **顶部细进度条 + "第 x 题/共 x 题"**——评委和用户都需要进度感 |
| 播放/暂停切换有过渡动画，不停顿跳变 | 暂停时字幕整体压暗 + 中央大暂停图标浮现，而不是只换按钮颜色 |
| 倍速/字号调节收进一个面板 | 语音指令已覆盖，补一个"长辈设置"入口说明（防误触确认弹窗，大纲里本就有） |

### C. 语音助手交互 → 答题与指令通道
**代表**：微信语音输入、小爱同学、讯飞听见

| 他们怎么做 | 我们抄什么 |
|---|---|
| 录音态是全屏最强视觉：声波 + 计时 + "我在听" | 录音时底部声波动效 + 大字"正在听您说…" + 已录秒数 |
| 识别文字**实时上屏**，不是结束才出现 | 现在是录完一次性回显——接阿里后争取流式回显；mock 期先模拟逐字出现的效果 |
| 没听清有明确重试话术 | "没听清"态设计：橙色提示 + 自动重问（后端 next_steps 已支持，补视觉） |

### D. 企业培训/考试 → 培训闭环的仪式感
**代表**：平安知鸟、云学堂、学习强国每日任务、安全教育平台

| 他们怎么做 | 我们抄什么 |
|---|---|
| 答对绿✓/答错红✗ 立即弹卡 + 解析 | 我们的"解析"由后端 next_steps 下发，前端补 **✓/⚠ 弹卡动画**（答错用橙不用红——橙色=需要巩固，红色=事故，对工人心理更友好，也贴合"赋能非处罚"的伦理定位） |
| 成绩单 = 得分圆环 + 错题列表 + 下次任务 | result 页重画：大得分 + 错题卡 + **"下次复训：x月x日"日历卡** + "明天班前见" |
| 每日任务清单勾选感 | 工人端结尾给"今日已完成"印章式视觉（班前会"签字归档"的数字化隐喻，评委看得懂） |

### E. 完成情况看板 → 管理端（最贴的一类！）
**代表**：群报数/群接龙（班组长真实天天用的）、企业微信汇报、钉钉智能报表、智慧工地人员状态板

| 他们怎么做 | 我们抄什么 |
|---|---|
| **完成/未完成一屏分两组**，未完成更醒目 | 看板工人列表改成两段式："未学 3 人"置顶（警示橙），"已学"置底（绿），组头带人数 |
| 未完成一键提醒 | 加"提醒未学工人"按钮（demo 期弹话术卡："建议班前会口头提醒/电话"——一键群呼是后端后话，按钮先立住场景） |
| 数据卡带昨日对比箭头 | 统计块加"较昨日 +1"小字（mock 数据即可，评审爱看趋势） |
| 日期可切换 | 看板加 今天/昨天 切换；明细行点开展开记录已有，保持 |

### F. 建筑蓝领工具 → 工种与场景视觉
**代表**：鱼泡网（招工）、工地实名制通道机

| 他们怎么做 | 我们抄什么 |
|---|---|
| 工种做成标签徽章 | 工人列表的工种统一徽章色（架子工/钢筋工/混凝土工…固定色板） |
| 电话级超大关键信息 | 看板的"未学人数"做成一屏最大数字——班组长最关心这一个数 |

## 2. 反面清单（成熟产品都**不做**的）

- ❌ 后台模板式：三四个色块一字排开 + 密集表格（现在管理端的样子，要改）
- ❌ 多层 tab 导航（目标用户不需要，管理端也不需要）
- ❌ 渐变大 banner、装饰插画、营销位（适老规范禁止干扰项）
- ❌ 弹窗广告化：任何非操作触发的弹层都不许出现
- ❌ 字号小于 28rpx 的正文（适老底线）

## 3. 落到我们的 12 条待办（映射关系）

| 对标结论 | 对应待办 |
|---|---|
| 规范 §0（字号/对比度/点击区/反馈） | 阶段0-1 设计规范 |
| WeUI 按钮/弹窗/Toast/空态语言 | 阶段0-1、阶段3-2 |
| A 大字确认页 + B 三级灰度 + 进度条 | 阶段1-2、1-3、1-4 |
| C 录音态全屏最强视觉 + 实时上屏 | 阶段1-2（mock 先模拟逐字） |
| D 成绩单仪式感 + "签字归档"印章 | 阶段1-4 |
| E 两段式完成/未完成 + 一键提醒 + 昨日对比 | 阶段2-1（看板重排） |
| F 工种徽章 + 关键数字最大化 | 阶段2-1、2-3 |
| 反面清单 | 全程约束，阶段3-3 走查时逐项对 |

## 4. 一句话结论

**工人端学"银行大字版 + 网易云歌词"，管理端学"群报数"**——前者给工人信任感，后者给班组长熟悉感。评委看到的不是"新奇的界面"，而是"这就是他们每天会打开的东西"，这才叫成熟。
